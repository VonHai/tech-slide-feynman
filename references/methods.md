## 一、理解类（4种）

### 1. 费曼技巧（Feynman Technique）
**来源**：物理学家理查德·费曼
**做法**：假装把概念讲给12岁小孩听，不用任何专业术语。讲不出来的地方=知识盲点。
**检验标准**：能用3句话讲清楚，且小孩能复述。
**典型句**："示例：网络分层概念——你从网络收到的是乱七八糟的箱子，不是整齐的商品。"
**适用**：所有概念性知识的理解检验。

### 2. 逐句翻译法（Line-by-Line Translation）
**做法**：PPT上每一句技术术语原文，逐句翻译成大白话，一句不漏。
**模板**：
```
原文：[PPT上的原话]
翻译：[大白话解释]
图解：[一句话图示]
```
**适用**：术语密集、看不懂的PPT页。

### 3. 词源拆解法（Etymology Breakdown）
**做法**：把术语拆到字母级别，讲清楚完整拼写、每个字母/音节的来源、记忆钩子。
**模板**：
```
术语：TTFT
完整拼写：Time To First Token
字母拆解：T(Time)-T(To)-F(First)-T(Token)
记忆钩子：到第一个字的时间
```
**适用**：缩写多、容易拼错的术语。

### 4. 苏格拉底螺旋学习（Socratic Spiral Learning）
**来源**：苏格拉底对话法 + 布鲁纳螺旋课程
**做法**：同一页PPT反复看3遍，每遍降一层抽象：
- 第1遍：高层概览（这页在讲什么大类）
- 第2遍：中层机制（每个概念怎么工作）
- 第3遍：底层原理（为什么这样设计，出处是什么）
**适用**：特别难、一遍看不懂的页。

## 二、直觉类（4种）

### 5. 生活类比法（Analogy Bridging）
**做法**：给每个技术概念找一个生活中的对应物，用熟悉场景理解陌生技术。
**类比库（可扩展）**：

| 技术领域 | 生活类比 |
|---------|---------|
| 网络传输 | 快递（箱子/包裹/商品/拆包/粘包） |
| 流式输出 | 外卖APP（菜/骑手位置/订单状态）、在线视频 |
| 延迟指标 | 外卖（看到接单/配送全程/吃到嘴里） |
| 适配器 | 翻译官（把各家方言翻译成普通话） |
| 网关/编码器 | 打包员/拆箱员 |
| 状态机 | 收快递流程（倒箱子→拼包裹→拆商品） |
| 取消/中断 | 刹车（轻刹/急刹/拉手刹） |
| 重试/恢复 | 断点续传（下载到一半断网，接着下不重来） |

**原则**：类比必须准确，不能为了类比而歪曲技术含义。

### 6. 图解法（Visual Thinking）
**做法**：把文字描述转成ASCII图，用空间关系代替线性文字。
**7种图解类型**：

| 类型 | 用途 | 示例 |
|------|------|------|
| 分层栈图 | 展示数据经过的层级 | Layer3→Layer2→Layer1 |
| 数据流向图 | 展示完整路径 | A→B→C→D |
| 对比图 | 正确vs错误 | ✅ xxx / ❌ yyy |
| 状态机图 | 处理流程 | 步骤1→步骤2→判断→步骤3 |
| Bug定位图 | 问题排查 | 现象→去哪层查→查什么 |
| 完整协议栈图 | 从底层到顶层 | 物理→IP→TCP→HTTP→应用 |
| 多屏幕/多维度图 | 并行展示 | 屏幕①/屏幕②/屏幕③ |

**原则**：图解必须能独立看懂，不能依赖文字解释。

### 7. 表格对比法（Comparative Table）
**做法**：用表格横向对比多个概念的区别，一目了然。
**常用对比维度**：出处/层级/谁负责/前端常接触吗/优先级/适用场景/不适用场景。

### 8. 口诀记忆法（Mnemonic Phrase）
**做法**：用朗朗上口的口诀总结核心要点，便于记忆和社交分享。
**典型口诀**：
- "你产生事件，框架编码，浏览器解码，OS传字节"
- "商品→包裹→箱子，倒出来拼好再拆"
- "TTFT到第一个字，GEN灯亮着那段，E2E从头到尾"

## 三、落地类（4种）

### 9. 代码映射法（Code-Driven Mapping）
**做法**：把每个技术概念映射到课程/项目代码中的具体文件、函数、行号，让抽象概念落地。
**模板**：
```
概念：[技术概念名]
代码：[文件路径] 第XX行，[函数名/代码片段]
作用：[这段代码在做什么]
```
**原则**：概念只有落到代码上才是"真懂了"。

### 10. Bug驱动法（Bug-Driven Learning）
**做法**：先讲"不懂这个概念会导致什么经典bug"，再讲"出问题怎么排查"，用痛点驱动理解。
**模板**：
```
不懂[概念]会导致：
  bug1：[现象] → [原因] → [定位] → [修复]
  bug2：[现象] → [原因] → [定位] → [修复]

排查流程：
  [问题现象] → [去哪一层查] → [查什么]
```

### 11. 反模式教学法（Anti-Pattern Teaching）⭐ 新增
**来源**：learn-anything 三结构教学法
**做法**：每个核心概念必须配一个反模式——不仅讲"什么是对的"，还讲"什么是错的、为什么这个错法很诱人、正确做法是什么"。
**为什么有效**：大脑对"错误+诱惑"的记忆强度远高于单纯的"正确做法"。知道坑在哪，比知道路在哪更重要。
**模板（每个核心概念必配）**：
```
❌ 反模式：[常见错误做法]
   后果：[会导致什么问题/bug/故障]
   为什么诱人：[新手为什么会自然地犯这个错——肌肉记忆/省事/看起来合理]
✅ 正确做法：[正确的做法是什么]
   为什么对：[底层原理是什么]
```
**示例（SSE Content-Type）**：
```
❌ 反模式：media_type="application/json"
   后果：浏览器EventSource拒绝连接，报错"MIME type not text/event-stream"
   为什么诱人：写HTTP接口的肌肉记忆就是application/json，顺手就写了
✅ 正确做法：media_type="text/event-stream"
   为什么对：浏览器靠Content-Type识别SSE流，不设就不认
```
**强制规则**：每个核心概念（一页PPT通常2-4个）必须配至少1个反模式。跳过反模式=教学不完整。

### 12. 学以致用发（Production Application）
**做法**：讲清楚"懂了这个概念在生产中怎么用"，给出具体场景、代码模板、Checklist。
**内容**：
- 3-5个必须用这个概念的生产场景
- 带注释的完整代码模板
- 上线前Checklist（5-10项）
- 常见坑列表（3-5个）

## 四、深挖类（3种）

### 13. 苏格拉底提问法（Socratic Questioning）
**做法**：连续追问，层层剥茧，逼近问题本质。
**6类追问**：
1. **澄清类**："这个概念到底是什么意思？"
2. **假设类**："如果不这样设计会怎样？"
3. **证据类**："这个结论的依据是什么？出处在哪？"
4. **视角类**："从前端/后端/运维角度分别怎么看？"
5. **后果类**："不懂这个会导致什么问题？"
6. **元认知类**："我为什么看不懂？缺什么前置知识？"

### 14. 逆向工程法（Reverse Engineering）
**做法**：从结果/代码反推设计原理和过程。
**步骤**：
1. 看最终代码/系统在做什么
2. 推测为什么这样设计
3. 验证推测（查文档/跑代码/问AI）
4. 总结设计原理
**适用**：架构设计、协议设计、框架源码学习。

### 15. 知识缺口诊断法（Knowledge Gap Diagnosis）
**做法**：分析"为什么看不懂"，指出缺哪些前置知识，给出补课路径和优先级。
**模板**：
```
诊断：你是[背景]，缺[前置知识领域]
缺口：[具体缺哪些概念]
补课：
  必须看：[资料1] [资料2]（解决核心问题）
  建议看：[资料3] [资料4]（帮助理解代码）
  暂时不用：[其他]
时间：[估算]小时补齐
```

## 五、验证类（3种）⭐ 新增

### 16. 3分钟测验法（3-Minute Quiz）
**来源**：learn-anything 自我评估+快速测验
**做法**：讲完一页PPT后，立刻出3-5道选择题/判断题，让用户当场作答，验证掌握度。
**为什么有效**："我以为我懂了"是最大的学习幻觉。测验是戳破幻觉的唯一可靠方法。主动回忆（retrieval practice）的记忆效果是被动重读的3倍。
**题目类型**：
- **概念题**：这个术语是什么意思？（检验理解）
- **判断题**：以下说法对不对？（检验反模式掌握）
- **场景题**：遇到XX情况该怎么做？（检验落地能力）
- **对比题**：A和B的区别是什么？（检验辨析能力）
**模板**：
```
### 3分钟测验（5题）

Q1：[概念题/判断题/场景题]
- A. [选项]
- B. [选项]
- C. [选项]
- D. [选项]

Q2：...

<details>
<summary>点击看答案+评分</summary>
答案：Q1-X, Q2-Y...
评分：5/5🟢掌握 / 4/5🟢进步中 / 3/5🟡学习中 / ≤2/5🔴弱
错题诊断：第X题错了→错误假设是XX→漏了YY前提→误区类型ZZ
</details>
```
**规则**：
- 必须在讲解完成后立刻出，不能等用户说"测验我"才出
- 题目必须覆盖：至少1道概念题+1道反模式/判断题+1道场景题
- 答案必须折叠（details标签），让用户先作答再看答案
- 每道错题必须配三步诊断（见方法18）

### 17. 理解度颜色卡片法（Mastery Color Card）
**来源**：mattdiep15/feynman 知识图谱节点着色
**做法**：每次讲解结束后，列出本次涉及的所有核心概念，每个标注理解度颜色，存入笔记持久化。
**颜色等级**：
| 颜色 | 等级 | 百分比 | 含义 | 判断标准 |
|------|------|--------|------|---------|
| 🔴 红 | Weak | 0-33% | 弱，有明显盲点 | 测验错≥2题，或解释不出来 |
| 🟡 黄 | Learning | 33-66% | 学习中，基本理解但不深 | 测验错1题，或能解释但不流畅 |
| 🟢 浅绿 | Improving | 66-90% | 进步中，比较熟但偶尔出错 | 测验全对，但需要提示才能完整解释 |
| 🟢 深绿 | Mastered | 90-100% | 掌握，能教给别人 | 测验全对，能独立流畅解释，能举反例 |
**模板（存入笔记）**：
```
### 理解度颜色卡片（第X页）

| 概念 | 颜色 | 说明 |
|------|------|------|
| SSE是什么 | 🟢 Mastered | 能独立解释，能举类比 |
| SSE帧格式 | 🟢 Improving | 字段都懂，但id和重连的关系还不熟 |
| Content-Type铁律 | 🟢 Mastered | 反模式清楚，能排查问题 |
| 心跳不占id | 🟡 Learning | 知道规则，但说不清为什么 |
| 拆包粘包 | 🔴 Weak | 概念模糊，客户端状态机写不出来 |
| buffer+状态机 | 🔴 Weak | 知道要累积，但4个状态说不清 |

下次学习重点：🔴拆包粘包、buffer状态机 → 🟡心跳不占id
```
**规则**：
- 每次讲解结束必须生成颜色卡片，存入笔记
- 颜色必须基于测验结果，不能凭感觉
- 必须标注"下次学习重点"（红色+黄色概念）
- 下次学习同一主题时，先读上次的颜色卡片，从红色概念开始

### 18. 错题三步诊断法（3-Step Error Diagnosis）
**来源**：learn-anything 错题诊断
**做法**：每道测验错题，不能只给正确答案，必须做三步诊断——找到思维缺口的根源。
**三步**：
1. **错误假设是什么**：用户选了什么？他为什么觉得这个对？他的隐含假设是什么？
2. **漏了什么关键前提**：正确答案依赖的哪个知识点用户没掌握？是概念混淆、前置知识缺口、还是场景判断错误？
3. **误区类型**：
   - **概念混淆**：把A和B搞混了（如SSE和WebSocket）
   - **前置缺口**：缺更基础的知识（如不懂TCP分包就不懂拆包粘包）
   - **场景判断**：知道概念，但不知道在什么场景用（如知道SSE但不知道聊天室该用WebSocket）
   - **记忆错误**：理解了但记错了细节（如把Content-Type记成application/stream）
**模板**：
```
错题诊断：
Q3你选了B，正确答案是C。
1. 错误假设：你以为SSE支持双向通信，因为它是"长连接"
2. 漏了关键前提：长连接≠双向，SSE的长连接只是服务器→客户端单向
3. 误区类型：概念混淆（把"长连接"和"双向通信"划了等号）

补课建议：复习SSE vs WebSocket对比表，重点看"方向"这一行
```
**规则**：每道错题必须配三步诊断，不能只说"正确答案是C"。

## 六、记忆类（2种）

### 19. 主动回忆法（Active Recall）
**来源**：认知心理学，效果优于被动重复学习
**做法**：合上书本和笔记，强迫自己凭记忆把刚学的内容写出来或说出来，再对照材料查漏补缺。
**具体操作**：
- 学完一页后，合上讲义，用3句话复述核心
- 学完一章后，默写知识框架
- 用闪卡（Anki）做概念问答

### 20. 间隔重复法（Spaced Repetition）
**来源**：艾宾浩斯遗忘曲线
**做法**：在遗忘临界点安排复习，将短期记忆转化为长期记忆。
**复习节奏**：
- 第1次：学完当天
- 第2次：1天后
- 第3次：3天后
- 第4次：1周后
- 第5次：1个月后
**工具**：Anki、SuperMemo、Obsidian间隔重复插件

## 七、元方法（1种）

### 21. 渐进式降级法（Progressive Simplification）
**做法**：用户说"还是不懂"时，从技术定义→生活类比→图解→口诀逐级降级，直到用户懂为止。
**降级链条**：
```
技术定义（最抽象）
    ↓ 不懂
生活类比（建立直觉）
    ↓ 不懂
图解（视觉化）
    ↓ 不懂
逐句翻译（拆到最小单位）
    ↓ 不懂
反模式教学（从错误角度理解）
    ↓ 不懂
口诀（最精简记忆点）
    ↓ 不懂
回到第1步，换一个类比/角度
```
**原则**：永远不要重复同一种解释方式，每次降级必须换方法。

> 注：原"对抗性阅读法"已合并入"苏格拉底提问法"的元认知追问（主动质疑每个结论的前提/反例/隐藏假设/代价），不再单独列为方法。

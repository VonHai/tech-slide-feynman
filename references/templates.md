## 逐页PPT讲解检查清单（18项）

拿到一页PPT，按以下顺序执行，每完成一项打勾：

```
□ 1. 浏览：快速扫一遍，抓标题/分层/关键词（30秒）
□ 2. 提问：苏格拉底式追问3个问题（这页讲什么？为什么需要？不懂在哪？）
□ 3. 逐句翻译：PPT上每句话都翻译成大白话（一句不漏）
□ 4. 生活类比：给核心概念找1-2个生活类比
□ 5. 图解：画1-2张ASCII图（分层图/流程图/对比图）
□ 6. 词源拆解：缩写术语拆到字母级别
□ 7. 表格对比：相关概念横向对比
□ 8. 代码映射：指出概念在代码中的具体位置
□ 9. Bug反例：不懂会导致什么bug，怎么排查
□ 10. 反模式教学：每个核心概念配"常见错+为什么诱人+正确做法"（强制）
□ 11. 生产应用：3个使用场景 + Checklist
□ 12. 费曼讲解：用3句话讲给12岁小孩听
□ 13. 口诀记忆：提炼1句朗朗上口的口诀
□ 14. 3分钟测验：出3-5道题（概念+判断+场景），验证掌握度（强制）
□ 15. 理解度颜色卡片：每个核心概念标🔴/🟡/🟢，存入笔记（强制）
□ 16. 存入笔记：完整内容存入学习笔记
□ 17. 主动回忆：合上笔记，复述3个核心点
□ 18. 安排复习：1天/3天/1周后复习
```

> **最低标准**：至少完成1-6 + 10 + 12 + 14 + 16（浏览→提问→翻译→类比→图解→词源→反模式→费曼→3分钟测验→存笔记）。
> **完整标准**：全部18项。
> **灵活调整**：简单页用5-7步，中等页用10-12步，困难页用全部18步。
> **三项强制**：反模式教学(10)、3分钟测验(14)、理解度颜色卡片(15)——任何页都不能跳过。

## 完整示例：网络分层概念

> 以下是用本方法讲解一页PPT的完整流程摘要，作为参考模板。

### 第1步 浏览（示例：网络分层概念）
- 标题：网络传输三层概念辨析
- 三层结构：LAYER1 HTTP传输层 / LAYER2 SSE帧协议 / LAYER3 Harness事件协议
- 常见错误：一一对应假设（1Token=1SSE=1Chunk）
- 正确姿势：客户端写成"无限字节流+状态机"

### 第2步 提问
- 这三层分别是什么？为什么要分三层？
- 为什么不能一一对应？拆包粘包是什么？
- 客户端状态机要怎么写？

### 第3步 逐句翻译（节选）
```
原文：把响应 Body 分批送到客户端
翻译：服务器不会把整个回答一次性发给你，而是切成一小块一小块陆续发

原文：buffer 累积 → lines 切分 → events 解析 → RunEvent
翻译：先把数据存起来→按空行切成一条条→看每条是什么类型→转成统一事件
```

### 第4步 生活类比
- Chunk = 快递箱（运输用的箱子）
- SSE Frame = 包裹（有面单+封口的单个包裹）
- Harness Event = 商品（包裹里真正的东西）
- 拆包 = 一个包裹拆成两个箱子
- 粘包 = 两个包裹塞进一个箱子
- 客户端状态机 = 收快递时倒箱子→拼包裹→拆商品

### 第5步 图解
```
商家发商品（业务层）
  ↓ 每件商品打一个包裹
3个包裹（SSE帧）
  ↓ 快递公司随便装箱，可能拆可能粘
2个大箱子（Chunk）
  ↓ 通过网线运到你电脑
你收到箱子（客户端）
  ↓ 倒出来→拼包裹→拆商品
看到3件商品（业务事件）
```

### 第6步 词源拆解
```
Chunk = 原词，"大块"的意思
SSE = Server-Sent Events（服务器发送事件）
Harness = 原词，"马具/治理框架"，套住野马
```

### 第7步 代码映射
- StreamingResponse → app.py，return StreamingResponse(...)
- encode_sse → app.py，def encode_sse(event)
- 客户端buffer状态机 → cli.py，buffer += line

### 第8步 Bug反例
- 不懂拆包粘包 → JSON解析报错、程序崩溃
- 不懂seq去重 → 事件重复显示
- 不懂Adapter边界 → 换模型前端全挂

### 第9步 费曼讲解
"示例：网络分层概念——你从网络收到的是乱七八糟的箱子（Chunk），不是整齐的商品（Event）。你必须自己把箱子倒出来、拼成完整包裹（SSE）、拆开拿到商品（Event）、检查有没有重复。这个过程叫客户端状态机。"

### 第10步 口诀
"商品→包裹→箱子，倒出来拼好再拆"

### 第11步 反模式教学（强制）

**反模式1：假设1Token=1SSE=1Chunk（一一对应）**
```
❌ 反模式：一次read()就是一条完整SSE事件，直接JSON.parse
   后果：拆包时半条SSE解析失败，粘包时三条SSE一起解析失败，程序崩溃
   为什么诱人：本地测试数据量小，每次read刚好一条，看起来"工作正常"
✅ 正确做法：buffer累积 → 按\n\n切分 → 不完整的留buffer → 逐条解析
   为什么对：TCP层会拆会粘，你控制不了，只能适应
```

**反模式2：用application/json当SSE的Content-Type**
```
❌ 反模式：StreamingResponse(media_type="application/json")
   后果：浏览器EventSource拒绝连接，报错"MIME type not text/event-stream"
   为什么诱人：写HTTP接口的肌肉记忆就是application/json
✅ 正确做法：media_type="text/event-stream"
   为什么对：浏览器靠Content-Type识别SSE流
```

### 第12步 3分钟测验（强制）

```
Q1：SSE的一条事件用什么分隔？
A. \n   B. \n\n   C. \r\n   D. --boundary

Q2：以下说法对吗？"一次TCP read()返回的就是一条完整的SSE事件"

Q3：你的SSE前端偶尔出现JSON解析失败，本地正常，最可能的原因是？
A. 服务器发了非法JSON   B. 拆包粘包，一次read拿到半条或多条
C. 浏览器不支持SSE      D. 网络太慢

Q4：SSE和WebSocket的核心区别是？
A. SSE更快   B. SSE是单向推送，WebSocket是双向通信
C. SSE更安全 D. 没有区别

Q5：SSE的心跳保活应该怎么发？
A. 带id的普通事件   B. event: heartbeat类型事件
C. 冒号开头的注释行  D. 不需要心跳
```

### 第13步 理解度颜色卡片（强制）

```
| 核心概念 | 颜色 | 说明 |
|---------|------|------|
```

## 记忆与复习策略

### 学完立即（当天）
- 主动回忆：合上笔记，用3句话复述核心
- 存入笔记：完整讲解内容写入Obsidian/笔记软件
- 标记难点：没完全懂的地方标红，后续重点复习

### 1天后
- 快速浏览笔记，重点看标记的难点
- 用费曼技巧再讲一遍（可以讲给朋友/录音）
- 做1道相关练习题或写1段相关代码

### 3天后
- 只看标题和口诀，尝试回忆完整内容
- 回忆不起来的地方，重新看笔记
- 更新笔记，补充新的理解

### 1周后
- 用闪卡（Anki）做概念问答
- 尝试在实际项目中应用这个概念
- 教给别人（最好的记忆方式）

### 1个月后
- 快速回顾，检查是否遗忘
- 遗忘的内容重新学习
- 构建知识图谱，把这个概念和其他概念关联起来
